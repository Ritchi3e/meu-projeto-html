Revisão prática: comandos de rede

Abra o CMD da sua máquina e realize as seguintes ações:

ipconfig
ipconfig /all
ping 8.8.8.8
ping google.com.br
tracert google.com.br
nslookup
uol.com.br

Digite o comando ipconfig e depois repita o comando adicionando o parâmetro no final: ipconfig /all. Em seguida, teste sua comunicação com o comando ping (ping 8.8.8.8 e ping google.com.br, ou qualquer outro site/domínio). Também verifique a rota até chegar ao destino com tracert google.com.br (ou o site/domínio usado no passo anterior).

Por fim, execute um nslookup para verificar quem está resolvendo os domínios para você.

Entendendo o resultado do nslookup: "Não é resposta autoritativa"

Na prática, o que isso significa? Basicamente, significa que o servidor DNS possui a informação, mas não é ele quem gerencia e controla isso — ele apenas responde porque tem a informação para responder à pergunta "quem é uol.com.br?". O destino de uol.com.br é o servidor 200.147.35.149.

O que é o encapsulamento de dados

O encapsulamento é responsável por empacotar as informações através dos protocolos, antes que essas informações sejam trafegadas pela rede.

À medida que os dados forem trafegando pelas camadas, cada camada pode adicionar informações — essas informações são para controle e gerenciamento dos dados. Essas informações adicionais são chamadas de cabeçalhos (headers) e trailers. Esse processo é o encapsulamento de dados.

FCS (Frame Check Sequence)

O FCS é um mecanismo de verificação da sequência de frames — resumidamente, é um cálculo matemático em cima dos dados que serão transmitidos. Se a sequência for alterada por qualquer motivo, a informação é considerada corrompida/comprometida durante a transmissão.

O receptor recebe a informação do FCS de origem e, quando os pacotes chegam até ele, é possível realizar o cálculo através do mecanismo para verificar se a sequência recebida está batendo com a origem, e se nenhuma informação foi alterada no percurso.

Como funciona na transmissão de dados

  • As camadas recebem as informações da camada superior, à medida que os dados descem pelas camadas adjacentes.
  • É acrescentado ao pacote de dados recebido as informações pelas quais a própria camada tem responsabilidade.
  • Os dados são repassados/transmitidos já encapsulados com as informações adicionais, para a próxima camada.

Cabeçalho (Camada de Enlace)

Trabalha na camada de enlace, onde os dados são organizados em estruturas que chamamos de frames. É composto principalmente por:

  • Endereço MAC de origem: identificando o dispositivo que enviou a informação.
  • Endereço MAC de destino: identificando o dispositivo que receberá a informação.

Trailer FCS (Frame Check Sequence)

É um código de verificação que permite ao receptor identificar possíveis erros que possam ter ocorrido durante a transmissão dos dados, garantindo que os dados sejam entregues corretamente entre dispositivos conectados na mesma rede física.

Cabeçalho de Rede

Trabalha na camada 3 (Rede), e aqui os dados são organizados em pacotes. Cada pacote possui um cabeçalho que contém informações cruciais para o roteamento e entrega dos dados através das diferentes redes existentes. As informações incluem:

  • Endereço IP de origem: identifica o endereço lógico do dispositivo de origem.
  • Endereço IP de destino: identifica o endereço lógico do dispositivo de destino.
  • Informações de roteamento: servem para auxiliar os roteadores a encaminharem o pacote pelo melhor caminho até alcançar o destino final.
  • Informações de fragmentação: dados que permitem a reconstrução correta do pacote, caso ele tenha sido fragmentado durante a transmissão por algum motivo.

Esses cabeçalhos são fundamentais para que os dispositivos, como roteadores, consigam direcionar os pacotes através das redes interconectadas até alcançarem o destino correto.

Encapsulamento, camada por camada

À medida que os dados são preparados para a transmissão, cada camada do Modelo OSI adiciona a sua própria informação (cabeçalho e, quando aplicável, trailer) à unidade de dados que foi recebida pela camada superior/anterior. Por exemplo:

  • Camada de Aplicação (C7): gera os dados originais que serão transmitidos.
  • Camada de Transporte (C4): encapsula os dados em segmentos, adicionando um cabeçalho com informações como número de porta e controle de fluxo.
  • Camada de Rede (C3): encapsula os segmentos em pacotes, adicionando o cabeçalho da rede, como endereço IP e informações de roteamento.
  • Camada de Enlace (C2): encapsula os pacotes em frames, adicionando o cabeçalho e o trailer do frame, com endereço MAC e informações para verificação de erros.
  • Camada Física (C1): converte os frames em sinais elétricos, ópticos ou de rádio para transmissão pelo meio físico.

Resumo

O Modelo de Referência OSI é uma estrutura mais conceitual, focada para estudos, que foi desenvolvida pela ISO. O modelo descreve funções de um sistema de comunicação de redes de computadores, divididas em 7 camadas. Cada camada possui responsabilidades distintas e pode interagir com as camadas adjacentes, facilitando assim a padronização e o funcionamento de diferentes sistemas e tecnologias.
