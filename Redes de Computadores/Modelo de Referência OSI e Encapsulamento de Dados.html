O que são protocolos de rede

A comunicação entre os dispositivos depende de regras e padrões que definem como os dados serão enviados, recebidos e interpretados — essas regras são implementadas através dos protocolos.

Existem diversos protocolos, cada um projetado para uma finalidade específica:

  • HTTP, HTTPS, FTP e SFTP: transferência de dados.
  • RDP, SSH: acesso remoto.
  • DNS: resolução de nomes.
  • SIP: comunicação de voz.
  • ICMP: diagnóstico de rede.
  • TCP e UDP: transporte de dados (informações).
  • SMTP/IMAP: envio e encaminhamento de e-mails, e receber/organizar e-mails, respectivamente.
  • SNMP: gerenciamento de dispositivos.

Não precisamos decorar os protocolos agora — primeiro vamos entender onde eles se encaixam. Um conjunto de protocolos utilizados em uma comunicação de dados também é conhecido como pilha de protocolos, e é essencial para garantir o bom funcionamento entre diferentes sistemas e redes.

Contexto histórico: por que o Modelo OSI surgiu

O desenvolvimento do modelo OSI ocorreu principalmente durante a década de 1970 e início dos anos 1980, e foi formalizado pela ISO em 1984, na referência clássica ISO 7498-1.

Na década de 80, as tecnologias de rede que surgiram foram criadas utilizando diferentes implementações de hardware e software. Cada empresa que criava hardwares e softwares para as redes utilizava seus próprios padrões, o que acabava gerando competição entre as companhias.

Consequentemente, muitas das novas tecnologias que frequentemente surgiam, fabricadas pelas empresas, eram incompatíveis umas com as outras — deixando cada vez mais difícil para as redes conseguirem se comunicar utilizando tecnologias distintas. Era frequentemente necessário remover o equipamento antigo para implementar um novo equipamento.

Surgiu então a necessidade de padronizar as redes, com um modelo que fosse fácil de usar e fácil de expandir. Assim nasceu o Modelo de Referência OSI.

O que é o Modelo OSI

Foi criado em 1971 e formalizado em 1983. É um padrão normativo para protocolos de comunicação entre os dispositivos que compõem uma rede local.

OSI é a sigla de Open Systems Interconnection, que podemos interpretar como "sistemas abertos à comunicação com outros sistemas".

O objetivo principal era ter uma base de referência e também desenvolver os protocolos envolvidos em cada camada. Cada camada tem responsabilidades e protocolos que trabalham em cima dela.

Princípios usados na criação do modelo

Os princípios básicos aplicados na criação do Modelo de Referência OSI, de acordo com Tanenbaum (2011), são:

  • Cada camada precisa ser criada onde houver um grau de necessidade diferente de abstração.
  • Cada camada deve executar e desempenhar funções que estejam bem definidas.
  • As funções de cada camada devem ser escolhidas tendo em vista os protocolos padronizados internacionalmente.
  • Os limites de camadas devem ser escolhidos para minimizar o fluxo de informação pelas interfaces.
  • O número de camadas deve ser grande o suficiente para que funções distintas não precisem ser colocadas desnecessariamente na mesma camada, mas pequeno o suficiente para que a arquitetura não se torne difícil de controlar.

Objetivos do Modelo OSI

  • Reduzir a complexidade dos dispositivos.
  • Padronizar as interfaces de comunicação.
  • Acelerar a linha de evolução.
  • Simplificar o ensino e aprendizado.

As 7 camadas do Modelo OSI

1. Física

Recebe e envia os bits brutos através do meio físico de transmissão.

  • Cabos de par trançado.
  • Fibra óptica.
  • Conexões sem fio (Wireless, Bluetooth).
  • Ethernet, USB e DSL.

2. Enlace de Dados

Garante a transferência confiável de dados entre dois nós diferentemente conectados, corrigindo erros que possam ocorrer na camada física.

  • Organização dos dados em frames e controle de acesso ao meio físico.
  • Protocolos: Ethernet e PPP.
  • Switches de Layer 2, que operam exclusivamente para encaminhar os frames com base nos endereços MAC dos dispositivos.

3. Rede

É responsável pelo endereçamento lógico e pelo roteamento dos pacotes de dados entre as diferentes redes. É nesta camada que se determina o caminho que os dados irão seguir para alcançar o seu destino.

  • Roteadores.
  • Protocolos: IP, ICMP, IPSec.

4. Transporte

É a camada que possui transferências confiáveis de dados de ponta a ponta, além de gerenciar o controle do fluxo e a correção dos erros de ponta a ponta.

  • TCP: Transmission Control Protocol.
  • UDP: User Datagram Protocol.
  • SCTP: Stream Control Transmission Protocol.

5. Sessão

Gerencia e controla as conexões e sessões ativas. É responsável por sincronizar a comunicação entre as aplicações e também por gerenciar a troca de dados.

É responsável por estabelecer uma sessão de login em um servidor e manter a conexão ativa até o logout intencional ou por timeout, de acordo com alguma regra de negócio configurada.

Protocolos e tecnologias associadas: NetBIOS, RPC, PPTP (Point to Point Tunneling Protocol), L2TP, IPSEC.

6. Apresentação

Responsável por traduzir os dados para um formato que a camada de aplicação consiga entender e aceitar: criptografia, compressão de dados e conversão de códigos de caracteres.

Exemplos:

  • Conversão de dados do formato EBCDIC para ASCII.
  • Criptografia de dados para transmissão segura da informação.

Protocolos e tecnologias associadas:

  • SSL (Secure Sockets Layer)
  • TLS (Transport Layer Security)
  • JPEG, MPEG (formatos de compressão de dados)

7. Aplicação

É a camada mais próxima do usuário final: é responsável por fornecer os serviços de rede que estão diretamente relacionados às aplicações. Permite que o usuário interaja com a rede mesmo não tendo um conhecimento técnico elevado, através dos softwares de aplicação.

Exemplos: navegadores web para acesso a páginas da internet, serviços de e-mail, stream de vídeos.

Protocolos e tecnologias associadas:

  • HTTP / HTTPS (Hypertext Transfer Protocol Secure)
  • SFTP (Secure File Transfer Protocol)
  • SMTP (Simple Mail Transfer Protocol)
  • DNS (Domain Name System)

Atividade prática: comandos de rede

Abra o CMD da sua máquina e realize as seguintes ações:

ipconfig
ipconfig /all
ping 8.8.8.8
ping google.com.br
tracert google.com.br
nslookup
uol.com.br

O comando tracert mostra a rota até chegar ao destino informado. Já o nslookup serve para verificar quem está resolvendo os domínios para você.

Entendendo o resultado do nslookup: "Não é resposta autoritativa"

Na prática, isso significa que o servidor DNS possui a informação, mas não é ele quem gerencia e controla isso — ele apenas responde porque tem a informação para responder à pergunta "quem é uol.com.br?". O destino de uol.com.br é o servidor 200.147.35.149.

Encapsulamento de dados

O encapsulamento é responsável por empacotar as informações através do uso dos protocolos, antes que essas informações sejam trafegadas pela rede. À medida que os dados vão trafegando pelas camadas do Modelo de Referência OSI, cada camada pode adicionar informações de controle e gerenciamento dos seus dados.

As informações adicionais são chamadas de cabeçalhos (headers) e, em alguns casos, de trailers. Esse processo é o encapsulamento de dados.

FCS (Frame Check Sequence)

O FCS é um mecanismo de verificação da sequência de frames — de forma simplificada, é um cálculo em cima dos dados que serão transmitidos. Se a sequência for alterada por algum motivo, a informação é considerada corrompida durante a transmissão.

O receptor recebe a informação FCS de origem e, quando o pacote chega, ele pode realizar o cálculo dos frames através do FCS e verificar a sequência recebida, para confirmar se está batendo com a origem.

Como funciona na transmissão de dados

  • As camadas recebem as informações da camada superior, à medida que os dados descem pelas camadas.
  • Cada camada acrescenta ao pacote de dados recebido as informações pelas quais a própria camada é responsável.
  • Os dados são repassados já encapsulados com as informações adicionais, para a próxima camada.

Cabeçalho do Quadro (Camada 2 - Enlace de Dados)

Aqui os dados são organizados em estruturas que chamamos de frames (quadros). O cabeçalho do quadro é composto por:

  • Endereço MAC de Origem: identifica o dispositivo que enviou a informação.
  • Endereço MAC de Destino: identifica o dispositivo destinatário da informação.

Trailer do Quadro

FCS (Frame Check Sequence): é um código de verificação que permite ao receptor identificar possíveis erros que possam ter ocorrido durante a transmissão dos dados, garantindo que os dados sejam entregues corretamente entre dispositivos conectados na mesma rede física.

Cabeçalho de Rede (Camada 3 - Rede)

Nesta camada os dados são organizados em pacotes. Cada pacote possui um cabeçalho que contém informações cruciais para o roteamento e entrega dos dados através das diferentes redes existentes:

  • Endereço IP de origem: identifica o endereço lógico do dispositivo de origem.
  • Endereço IP de destino: identifica o endereço lógico do dispositivo de destino.
  • Informações de roteamento: auxiliam os roteadores a encaminharem o pacote pelo melhor caminho até alcançar o destino final.
  • Informações de fragmentação: permitem a reconstrução correta do pacote, caso ele tenha sido fragmentado durante a transmissão por algum motivo.

Esses cabeçalhos são fundamentais para que dispositivos como roteadores consigam direcionar os pacotes através das redes interconectadas, até alcançarem o destino correto.

Exemplo completo de encapsulamento, camada por camada

À medida que os dados são preparados para a transmissão, cada camada do Modelo OSI adiciona a sua própria informação (cabeçalho e, quando aplicável, trailer) à unidade de dados recebida da camada superior/anterior. Por exemplo:

  • Camada de Aplicação (C7): gera os dados originais que serão transmitidos.
  • Camada de Transporte (C4): encapsula os dados em segmentos, adicionando um cabeçalho com informações como número de porta e controle de fluxo.
  • Camada de Rede (C3): encapsula os segmentos em pacotes, adicionando o cabeçalho de rede, como endereço IP e informações de roteamento.
  • Camada de Enlace (C2): encapsula os pacotes em frames, adicionando o cabeçalho e o trailer do frame, com endereço MAC e informações para verificação de erros.
  • Camada Física (C1): converte os frames em sinais elétricos, ópticos ou de rádio para transmissão pelo meio físico.

Resumo

O Modelo de Referência OSI é uma estrutura conceitual, de referência e estudos, desenvolvida pela ISO. O modelo descreve funções de um sistema de comunicação de redes de computadores, divididas em 7 camadas. Cada camada tem responsabilidades distintas e pode interagir com as camadas adjacentes, facilitando a padronização e o funcionamento de diferentes sistemas e tecnologias.
